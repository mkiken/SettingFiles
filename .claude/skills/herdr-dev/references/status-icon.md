# Herdr shell status icon mirroring

The plugin side of the label rebuild is in `notify-rich.md` — change both together.

Non-AI shell state icons (input-wait ✋ from `_start_prompt_wait_notification`/`_finish_prompt_wait_notification` in `shell/zsh/alias/utils.zsh`, and long-command completion ✅/failure ❌ from the `shell/zsh/notification.zsh` precmd/preexec hooks) mirror to Herdr the same way tmux gets them: `notify --tmux-icon` (`shell/zsh/alias/notification.zsh`) now also calls `shell/tmux/herdr_status_icon.sh`'s `update_herdr_status_icon`/`remove_herdr_status_icon` whenever `TMUX` is unset and `HERDR_ENV`/`HERDR_PANE_ID` is set (tmux and Herdr are mutually exclusive, so both call sites are safe to run unconditionally). A normal (non-popup) Herdr pane exposes `HERDR_PANE_ID`/`HERDR_TAB_ID`/`HERDR_WORKSPACE_ID` directly as env vars — no `herdr pane get` round-trip needed, unlike the popup-only `HERDR_ACTIVE_PANE_ID` case documented in `popups.md`. Tab labels are updated last-write-wins (mirroring tmux window names); the AI identifier prefix (✴️/💎/🪷) already on a label is preserved and only the status glyph is swapped, via `tmux_window_name.py`'s `compute-updated-label`/`compute-cleaned-label` CLI subcommands — pure functions that compute a label string without touching tmux or `herdr`, so Herdr's shell script can reuse the exact same prefix logic as the tmux hooks. Workspace-level aggregation is shell-only: `herdr_status_icon.sh` stores each tab's ✋ marker or ✅/❌ state in its cache, then OR-aggregates only those records (priority ✋>❌>✅) via `herdr workspace report-metadata <id> --source shell-status --token shell_status=<emoji>`. Never derive this token from tab labels: notify-rich writes AI glyphs to the same labels, which would leak stale or unrelated AI state into Spaces. The sidebar surfaces only `$shell_status`; AI state belongs in the Agents sidebar. This config requires `herdr server reload-config` because it is not live-reloaded like symlinked shell scripts.

Tab labels have THREE writers: herdr-automatic-rename owns the exact outer `[1-9] ` jump-key prefix, notify-rich rebuilds the AI identifier + agent-status glyph + emoji-stripped base on pane.focused / agent_status_changed / agent_detected, and these shell functions temporarily replace the status glyph. `tmux_window_name.py`'s pure `compute-updated-label` / `compute-cleaned-label` preserve that outer index while changing only the inner body; normal tmux update paths do not use this Herdr-specific handling.

`herdr-tab-label` and `worktree-task` also use this module for a one-time manual base-label replacement. `set_herdr_task_tab_label` delegates to `compute-initial-task-label`, which replaces only a Herdr default base, preserves the three writers' current prefixes, and limits the task slug to 20 characters. Because the new base is manual, notify-rich preserves it while continuing normal status updates; no persistent marker or fourth ongoing writer is introduced. `set_herdr_worktree_tab_label` remains only as an already-loaded-prompt compatibility wrapper.

A shell-set glyph is stomped within seconds unless protected. The input-wait ✋ is therefore made sticky via an out-of-band ownership marker (label text alone cannot distinguish a shell ✋ from a plugin ✋ that must revert to 🤖 when the agent resumes): `update_herdr_status_icon "✋"` writes `${XDG_CACHE_HOME:-$HOME/.cache}/herdr-shell-status/<sanitized socket>/<sanitized tab_id>` before renaming, any other glyph or `remove_herdr_status_icon` deletes it, and the plugin pins the glyph back to ✋ via `tmux_window_name.py compute-updated-label` while a valid marker exists (24h-TTL backstop, stale/garbage markers self-delete on read). The shell owns the ✋ lifecycle; ✅/❌ stay last-write-wins by design (focus-strip acts as acknowledgment). When changing the index, plugin label rebuild, or shell icon functions, re-run `tests/terminal/herdr/plugins/notify_rich/test_herdr_plugin_toml__herdr_plugin_notify.py`, `tests/shell/tmux/test_tmux_window_name.py`, AND `tests/shell/tmux/test_herdr_status_icon_sh.py` together.
