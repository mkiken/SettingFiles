# Herdr installer integrations (`mac/scripts/herdr.sh`)

`mac/scripts/herdr.sh` runs the official Claude and Codex installers in isolated staging, validates their registrations against the managed configuration, then transactionally deploys the hook scripts. Never run `herdr integration install` against live Claude or Codex configuration, especially the managed `~/.codex/hooks.json`; always use the repository helper. Gemini has no installer integration and relies only on Herdr's screen-manifest detection. This is the herdr→AI direction (detection/state reporting); the reverse AI→herdr direction (an agent driving the `herdr` CLI) is a separate concern handled by the vendored `ai/common/skills/herdr/SKILL.md` (see Standalone skills in the root CLAUDE.md). `sync_herdr_skill` (`mac/scripts/common.sh`), called once from `mac/updates/claude.sh` before `setup_ai_skills`, pulls the upstream `SKILL.md` on every `mac/update` and overwrites the vendored copy on a diff — but never stages it, so a human always reviews the change via `git diff` before committing.

`setup_herdr` takes a trailing `mode` argument (`install` from `mac/initialization/herdr.sh`, `update` from `mac/updates/herdr.sh`, default `update`) and forwards it only to `setup_herdr_integrations`. In `install` mode, the staging installer is skipped when the three deploy artifacts it produces (both hook scripts plus the Claude `settings.json` SessionStart registration) are already present — a fresh machine still runs it. `update` mode always runs it, since a herdr binary upgrade needs the new hook script reflected. `setup_herdr_config` and `setup_herdr_plugins` already self-guard (symlink match / `herdr plugin list` check) and take no mode. `setup_herdr_service` no longer calls `brew services restart` at all — restarting tears down a running server and can take down every open Herdr pane mid-session — it now calls `brew services start` only when the service isn't already `started`, regardless of mode; after a herdr binary upgrade, restart the service manually. Required tests: `tests/mac/scripts/test_herdr_sh__herdr_setup.py` (`HerdrIntegrationsModeTest`, `SetupHerdrOrchestrationTest`, `HerdrServiceSetupTest`, `HerdrSetupCallSiteModeTest`).

Plugin runtime behavior (notify-rich internals, hookable events) is in `notify-rich.md`; the environment plugins and popups run under is in `plugin-env.md`.

Remote plugins are declared in `HERDR_REMOTE_PLUGINS`. `herdr-automatic-rename` is configured through the tracked `terminal/herdr/herdr-automatic-rename-config.sh`, symlinked to `~/.config/herdr-automatic-rename/config.sh`. Create or validate that symlink before installing remote plugins: the upstream default `NAME_TABS=1` would otherwise create a window where it can replace notify-rich's conversation-summary labels. The managed setting is `NAME_TABS=0` with `AUTO_INDEX=1`; automatic-rename owns only the outer `[1-9] ` jump-key prefix. Refuse to overwrite a regular file or unexpected symlink at the live config path. Required tests: `tests/mac/scripts/test_herdr_sh__herdr_setup.py` (`HerdrPluginSetupTest`).
