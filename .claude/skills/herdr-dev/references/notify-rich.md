# Herdr notify-rich plugin and the Gemini notification split

The plugin's runtime environment and the debug/reload loop: `plugin-env.md`. The plugin also rebuilds tab labels on every focus/status event, which stomps shell-set glyphs; the ✋ ownership-marker contract it must honor is in `status-icon.md`.

## macOS delivery

Notify-rich sends through `HERDR_BIN_PATH notification show`, which honors `[ui.toast] delivery = "system"` and gives macOS a stable Herdr notification identity. Homebrew `terminal-notifier` 2.0.0 is unsigned and can return exit 0 while modern macOS suppresses it; keep it only as an API-failure fallback. Map done to Herdr's `done` sound and blocked/error to `request`. Verification requires both a successful plugin log and user-visible receipt: first trigger a dedicated status transition, then send `herdr notification show` directly to separate plugin logic from OS delivery.

## Tab label writer contract

Tab labels have three cooperating writers: `herdr-automatic-rename` owns only the exact outer `[1-9] ` jump-key prefix; notify-rich owns the AI identifier, agent-status glyph, and conversation-summary base; the shell status integration temporarily replaces only the status glyph. Notify-rich must split `[1-9] ` before default/manual-label classification and state-file comparison, rebuild the unnumbered body, then restore the prefix immediately before rename. Never store the index in `last_auto_label` or include it in notification `screen_label`; repeated focus/status/detected events must not stack prefixes or emoji. Prefixes outside the exact one-digit form are ordinary label text. On `pane.focused` the plugin additionally clears the shell-owned ✅/❌ (`clear_herdr_shell_status_state`) before the rebuild block and before the gemini guard — see `status-icon.md` for why the ordering is load-bearing. Required tests: `tests/terminal/herdr/plugins/notify_rich/test_herdr_plugin_toml__herdr_plugin_notify.py`, `tests/shell/tmux/test_tmux_window_name.py`, and `tests/shell/tmux/test_herdr_status_icon_sh.py`.

`herdr-tab-label` and `worktree-task` share a one-time base-label replacement through `set_herdr_task_tab_label`, using the descriptive slug without the `task/` namespace or timestamp. `compute-initial-task-label` replaces only a Herdr default base; a manual base is returned unchanged. It preserves the current index, identifier, status glyph, and context badge while limiting the base to 20 characters. The resulting slug is an ordinary manual label: notify-rich keeps it instead of adopting Claude's conversation title, but continues rebuilding identifier/status glyphs. The legacy `set_herdr_worktree_tab_label` name remains a compatibility wrapper for already-loaded prompts.

## Hookable events

Plugin `[[events]]` hooks accept only a subset of the socket API's Subscription events — never infer hookability from `herdr api schema` (its Subscription list includes `pane.updated`, which the hook registry rejects). Measured on herdr 0.7.5 — valid: `pane.{created,closed,exited,focused,moved,agent_detected,agent_status_changed}`, `tab.{created,closed,focused,renamed,moved}`, `workspace.{created,updated,renamed,moved,closed,focused}`, `worktree.{created,opened,removed}`; rejected as non-fatal `unknown event` link warnings: `pane.updated`, `pane.output_matched`, `pane.scroll_changed`, `layout.updated`, `workspace.metadata_updated`. Cheapest check: link a throwaway plugin listing every candidate event and read the warnings from `herdr plugin list`. Also measured live (0.7.5): an OSC 2 terminal-title change fires NO hookable event (verified with an all-valid-events probe plugin while injecting `printf '\033]2;…'` into a pane tty — nothing fired), so conversation-summary tab labels refresh only on agent_status_changed / agent_detected / focused. Claude Code often updates its summary title after the turn's `done` event, which is why a tab label (and the sidebar) can lag one summary behind until the pane is next focused. A structural fix would be a long-lived subscriber on the socket API, whose Subscription list DOES include `pane.updated` — unverified, separate task.

## Gemini's opt-out

Gemini opts OUT of `notify-rich` entirely (notification AND tab rename — see the `agent=="gemini"` guard near the top of `notify-on-agent-status.sh`), because its `agent_status` is derived solely from screen-manifest detection and oscillates `done`↔`working`↔`idle`, firing the plugin's notification gate many times per response and flooding Mac notifications. Gemini instead notifies via its own `AfterAgent`/`Notification` tmux hooks (`ai/gemini/hooks/notification.sh`), whose `IN_HERDR` guard around the notification body was relaxed so it fires under Herdr too (the ToolPermission filter for the `notification` event still applies under Herdr; only the tmux-icon calls stay Herdr-gated, since they're no-ops there anyway). Claude/Codex keep the installer-reported state accurate and stay managed by `notify-rich`. When touching either side of this split, update both together and re-run `tests/terminal/herdr/plugins/notify_rich/test_herdr_plugin_toml__herdr_plugin_notify.py` and `tests/ai/gemini/hooks/test_notification_sh__gemini_herdr_notification.py`.

## Notification body per agent

Conversation-title tab labeling (the `title_usable` check in `notify-on-agent-status.sh`) is further narrowed to claude only: codex also sets `terminal_title_stripped` to a conversation summary but keeps only its identifier emoji + status icon, since the summary is far less meaningful for codex tabs. The notification BODY is split the same way: claude uses `terminal_title_stripped` (unless editor-owned — see "Editor-owned titles" below), codex replaces it with a transcript-derived summary (same `build_session_summary` format as the tmux hooks) — the plugin resolves the rollout JSONL from `pane get`'s `agent_session.value`, which IS codex's `session_id` (reported by `~/.codex/herdr-agent-state.sh` from the SessionStart hook input), via `codex_hook_common.py analyze`. Codex's choice prompts fire no codex hook, so notify-rich must remain codex's single notifier under Herdr; only the body text is enriched, with fallback to the raw title on any failure. Two constraints: the plugin env's `python3` is system 3.9, so `codex_hook_common.py` needs its `from __future__ import annotations` (PEP 604 annotations would crash at def time); and zsh's builtin `echo` expands backslash escapes, so the summary helpers run under `setopt bsd_echo` inside a scoping subshell. When touching this split, re-run `tests/terminal/herdr/plugins/notify_rich/test_herdr_plugin_toml__herdr_plugin_notify.py`'s codex-labeled and codex-summary cases plus `python3 -m unittest discover -s ai/codex/hooks`.

## Editor-owned titles

`title_usable` is also narrowed by title ORIGIN: `terminal_title_stripped` reflects whichever program currently owns the pane's OSC 2, and `agent == "claude"` is a pane attribute, not the title's author — while Claude Code waits on `$EDITOR`, nvim owns the title (measured live: `claude-prompt-<uuid>.md (/private/tmp/claude-501) - Nvim`; modified buffers add ` + `). `tmux_window_name.py is-editor-set-title` rejects such titles for both the tab label and the claude notification body (body falls back to the state file's `last_auto_label`, else `(no title)`). The predicate matches ONLY a closed set — `claude-prompt-` prefix and VCS message names (`COMMIT_EDITMSG` etc.) — applied to the basename of the first whitespace-separated token (basename of the whole title breaks on the suffix path's slashes; whole-title equality makes the VCS rule dead code). Do NOT generalize to extension/no-space heuristics: measured live, ~40% of conversation summaries are no-space hyphen slugs, so that silently drops legitimate summaries like `update-readme.md`. Keep `is_editor_set_title` separate from `is_herdr_default_label` (different questions: "may this label be overwritten" vs "is this title trustworthy as a summary"); merging would turn manually named tabs like `notes.md` auto_managed. This predicate call alone is fail-closed in the plugin (only exit 1 adopts; crashes/usage errors reject) — asymmetric with `is-herdr-default-label` on purpose, since failing open here lets corruption through. Known limits: other OSC 2 emitters not in the closed set can still pollute labels (the structural fix would be `herdr pane process-info`'s `foreground_processes[]` — unverified, separate task), and a legitimate summary slug starting with `claude-prompt-` gets rejected. Never "clean up" a polluted tab-label state file: while its line 1 exactly matches the current label the `auto_managed` anchor survives and the next real summary self-heals it; deleting the file demotes the tab to manually-named and freezes the bad name permanently.

## Claude done-gating

Claude's `done` notification in notify-rich is gated by the same `PENDING_BACKGROUND_WORK` transcript analysis as the tmux Stop hook (`claude_transcript_analyze.py`; transcript resolved from the pane's `agent_session.value` via `resolve_host_transcript`), because the tmux hook exits immediately under `HERDR_ENV` and its guard never runs there: a turn end while async Agent completions are outstanding or a ScheduleWakeup is armed sends no completion notification. Bash `run_in_background` stays out of scope by analyzer design (a long-lived background server would suppress completion notifications indefinitely). The guard is fail-safe — unresolved transcript or failed analysis falls back to notifying — and applies to `done` only (`blocked` always notifies). Tests: the `claude_transcript`-labeled cases in `tests/terminal/herdr/plugins/notify_rich/test_herdr_plugin_toml__herdr_plugin_notify.py`; the fixture isolates `CLAUDE_CONFIG_DIR` the same way `CODEX_HOME` is isolated.

## `herdr notification show` exit code vs. delivery

`herdr notification show` exits 0 even when `[ui.toast] delivery = "off"` suppresses the toast — the response body carries the real outcome (`{"result":{"shown":false,"reason":"disabled"}}`). The terminal-notifier fallback (`notify-on-agent-status.sh`, near the end) must parse `.result.shown` from the captured stdout, not just check the exit code — an exit-code-only check silently swallowed every notification while `delivery="off"`, because the fallback branch became unreachable. Regression test: `test_toast_disabled_falls_back_to_terminal_notifier` in `tests/terminal/herdr/plugins/notify_rich/test_notify_on_agent_status_sh__notify_on_agent_status_full.py`, which stubs `notification show` to return `shown:false` via `HERDR_STUB_NOTIFICATION_SHOWN`.
