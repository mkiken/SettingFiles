# Herdr popups and the `[[keys.command]]` environment

When a `[[keys.command]]` popup needs to act on the pane that triggered it (not the popup itself), read `HERDR_ACTIVE_PANE_ID` / `HERDR_ACTIVE_PANE_CWD` — `HERDR_PANE_ID` is unset inside a popup and only identifies the popup pane itself. Confirmed by injecting a probe binding and inspecting `env | grep HERDR` from inside a live popup. `HERDR_ENV=1` and the `HERDR_ACTIVE_*` vars are injected (confirmed by dumping `env` from a live popup). Popup commands run as children of the herdr server with a stripped environment (`PATH`, possibly `LANG`) — read `plugin-env.md` before writing any command that invokes user tooling or handles multibyte text. Launch anything that needs user tooling via a login shell (`zsh -ilc "..."`) so `~/.zprofile`'s `brew shellenv` restores PATH — with non-login `zsh -ic`, Homebrew tools are missing during zshrc init (`managed.zsh`'s `brew --prefix` fails and cannot repair PATH either). `herdr pane send-text <pane_id> <text>` takes exactly two positional arguments and does not treat `--` as an end-of-options separator — passing one leaks a literal `--` into the inserted text; pass the two arguments directly.

`prefix+ctrl+g` lazygit is the exception: `worktree-task` can operate in a Git worktree without changing the AI pane's cwd. Its popup therefore resolves the active tab through `HERDR_ACTIVE_PANE_ID`, then reads the task path from `shell/tmux/herdr_worktree_context.sh` before falling back to `HERDR_ACTIVE_PANE_CWD`. The workflow records that context only after worktree validation and clears it after the task worktree entry is gone; the launcher self-clears stale paths. Keep this routing lazygit-specific unless a new popup explicitly needs task-worktree semantics.

Before reloading config from a secondary worktree, check `readlink "$HOME/.config/herdr/config.toml"`: the live symlink can point at another worktree, so reloading the current checkout's config has no effect.

An interactive login shell used only to load aliases/functions can fail before its popup command runs: Powerlevel10k's gitstatus initialization attempts `setopt monitor`, which Herdr's popup PTY rejects, then the `zsh -ilc` child exits immediately. Set `HERDR_POPUP_COMMAND=1` on such bindings; `shell/zsh/managed.zsh` uses it to skip prompt-theme initialization while still loading commands such as `frws`. Pin both the binding and the skip gate in tests.

Sending the first command to a freshly created pane (`pane split`/`tab create` + `pane run`) races with shell startup: input sent during zshrc init is dropped, and `pane wait-output --source recent` matches the input-echo line, so a single-form marker false-positives before the shell is ready. Gate the first real command behind the shared `_herdr_wait_shell_ready` (`shell/tmux/herdr_wait_shell_ready.sh`, sourced by `ai.zsh` and `herdr-split-snapshot-pane.sh`) — split-token marker + per-attempt unique marker + short-timeout retries + a `ctrl+u` line clear once ready — instead of re-implementing markers inline.

The marker must be unique per attempt. `pane wait-output --source recent` searches a cumulative snapshot, so a reused marker makes every later wait match the first attempt's output and readiness is declared while zshrc is still initializing; the real command then lands in a line buffer holding unconfirmed input and is echoed as an argument (`print -r -- <real command>`) instead of executed. This was the cause of `freview`'s codex tab silently never starting its review. Three alternatives are measured dead ends — do not re-litigate them:

- **`wait-output --lines <N>` cannot bound the search.** It slices N lines from the top of a fixed-height grid, not the tail, so shrinking N drops the current attempt's output too (measured on a pane with 4 visible lines: NOMATCH for `--lines 1..50`, MATCH only at 100+; `pane read --source recent --lines 5` returns empty while `--lines 100` equals unbounded). A loop built with `--lines 3` scored attempts=12 ok=0 on a healthy pane, turning an intermittent failure into a permanent one.
- **`pane process-info` is not a readiness probe.** On a freshly created pane `foreground_process_group_id == shell_pid` holds from the very first sample (a zshrc-executing shell is its own foreground process), so it reports ready exactly during the interval you need to wait through. It does detect "another process owns the foreground" (a Claude-running pane shows them differing), which is a different question.
- **`pane send-keys <id> ctrl+u` is a no-op before ZLE starts.** Measured: eight sends, then the real command was echoed but never executed. It is only useful once ready, to clear the line the real command will land on.

Do not verify command landing by string-matching pane output: `shell/zsh/history.zsh`'s `share_history` + `inc_append_history` make a new shell restore other sessions' history lines, so the same string can appear without the command having run — and zsh-autosuggestions renders a history-derived completion as ghost text on the prompt line, so even a *visual* read of the pane shows a full command that was never typed (distinguishable only by its SGR color: `38;5;2` typed vs `38;5;8` ghost). Verify landing with a file marker instead (below). Do not write multi-step herdr orchestration inline in config.toml `[[keys.command]]` strings; the TOML→bash→pane-run quoting layers are error-prone — put the flow in a `~/.tmux/scripts/` script (symlinked via `mac/initialization/tmux.sh`) and call it with one line.

`herdr pane run` can intermittently deliver a command line with its tail dropped, even after a successful `_herdr_wait_shell_ready`. Length is not the deciding factor and shortening the command is not a sufficient fix: first observed on freview's 141-char watch command (lost exactly its final ` codex.md=<tab_id>` argument, watching 2/3 AIs), then again on a bare 13-char `_review_watch` whose trailing Enter was dropped, leaving the command sitting unexecuted on the prompt. Both happened under the load of 3 AI CLIs booting simultaneously. Treat every `pane run` as unreliable delivery and apply all three:

- **Never carry a value that must be exact in the keystroke payload.** `workspace create` / `tab create` accept `--env KEY=VALUE`, which reaches the pane's interactive shell (live-verified on herdr 0.7.5); the receiver reads it as a fallback for an omitted argument. A truncated path is worse than a missing one — it can silently resolve to a *different, valid* run and act on it.
- **Pass long argument lists via a file** the receiver reads back (`_review_watch` + `${run_dir}/watch_specs`).
- **Verify landing with a file marker, then re-send.** The receiver touches a marker under a per-run directory (`${run_dir}/watch_started`) as its first act; the sender polls for it and, on timeout, sends `ctrl+u` (clears the stranded partial line) and re-runs, up to a few attempts before failing loudly with the manual recovery command. A per-run directory means the marker cannot be stale, which is why this works where output matching does not. See `_herdr_send_watch_verified` in `shell/zsh/alias/ai/ai.zsh`.

Make the receiver fail loudly when the path, file, or env value is missing so a truncated send surfaces instead of silently degrading.
